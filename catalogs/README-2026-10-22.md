## Methodology

Primary indexes:
- [Carter54git / Greates Games Decompilations List](https://github.com/Carter54git/Greates-Games-Decompilations-List), grouped by the **original platform** (October 20, 2026).
- [wangxiaoxiang5599 / Recompiled Games List](https://github.com/wangxiaoxiang5599/recompiled-games-list), concentrating on console native PC recompilations and ports (October 21, 2026).
- Background cross-reference: [SubmitGame / awesome-decomp-games](https://github.com/SubmitGame/awesome-decomp-games).

The scout extracts GitHub repository-root URLs, deduplicates repeated source
projects and entries already in the original 298-repository manifest, and
prioritizes significant series, ports/reimplementations, and projects present
in the second index. It also considers archived repository entries important
for preservation. Some repository names collide in the target Gitea
organization: non-conflicting entries are routed to `mirrors`; seven remaining
destination collisions are excluded for later manual handling.

**Confidence is intentionally separated:** 73 URLs were checked directly
using GitHub's public repository metadata API. This confirms the repository
existed, was accessible and reported nonzero content at check time; it does
**not** verify that a port works, a decomp matches, dependencies are safe, or
the claimed platform is accurate. The remaining 2,017 are *index-derived
discovery candidates*, not individually verified. Two repositories returned
404 during spot checks and were excluded from immediate mirroring:
`fabioap-cpu/Tekken3Recomp` and `carlosrmz009/littleplanet`.

## Scope and interpretation

- A **matching decompilation** aims to regenerate equivalent original machine
  code; a **functional reconstruction** might not match.
- **Static recompilation** usually translates console machine code ahead of
  time to run on a different CPU/platform.
- A **source port** rebuilds or adapts code to another operating system.
- An **engine reimplementation** reproduces engine behavior from scratch and
  generally needs game assets supplied by the user.
- A **PS4 or PS5 native runtime** may execute original x86-64 game code with
  reimplemented platform services and graphics translation. This is
  **not** the same as obtaining or reconstructing game source code.
- `category` in the manifest combines a platform or project family with the
  index-reported method. It's an importer preview annotation, **not** Gitea
  tags/topics automatically written to the repository.
- These catalog files host **source links only**. They do not provide game
  binaries, ROMs, ISOs, license keys or extracted copyrighted assets.
  Existing projects can require legally obtained original game data.

## Operational safety

Both Gitea organizations `decomps` and `mirrors` must exist and the
companion must have access to GitHub. Each imported URL has an explicit
destination override. These manifests do **not** delete, move or rewrite
previously mirrored repositories.

Don't treat a successful import as proof that every project was cloned:
inspect the mirror status afterward. Never rely on a pull mirror alone to
preserve branches deleted between synchronization intervals; take independent
Git snapshots and preserve LFS/releases separately.

This is a **public project-discovery snapshot**, not a guarantee of
completeness, source authenticity, build correctness, or ongoing availability.
